# 角色扮演文件（人格卡）

每个角色一个 Markdown 文件，**文件名 = 角色名**（不含扩展名，中英文均可）。例：`roles/傲娇助手.md`。

在群里对 QQ agent 说 `进入角色扮演：<角色名>`，或在控制台「人格与角色」页点选启用；说 `退出角色扮演` 恢复正常。

---

## 一、人格卡只写「人设」，不写「怎么干活」

这是最重要的一条。提示词分两层：

| 层 | 放在哪 | 管什么 |
| --- | --- | --- |
| **通用系统预设** | `dsh/agent-presets/qq-chat-v2/agent.cordis.yml` 的 `persona.prefix` | **安全、硬约束、工具**：权限边界、发送规则、工具协议、控制标记 |
| **人格模板** | 本目录的 `roles/<角色名>.md`（同步到人格配置的 `system` 层） | **你是谁与怎么说话**：身份、性格、语气、格式、聊天习惯、梗、雷点、关系 |

**不要把工具用法写进人格模板。** 原因：

- 工具协议统一由通用系统预设负责，人格模板重复写会和预设里的规则打架；
- 人格模板只应放性格、格式与习惯；安全/硬约束/工具调用由预设唯一权威；
- 表情包、记忆、看图、合并转发、引用等能力，预设里已有完整章节，人格模板再写一遍只会占预算并产生冲突。

人格模板里写工具说明的典型症状：模型照着一份过时的工具说明发消息，或者和预设里的调度规则互相矛盾。

---

## 二、需要区分模式时：在标题里加标记

同一个角色如果确实需要「一代这样说、二代那样说」，用**标题级模式标记**，桥接会只注入当前模式适用的小节：

```markdown
## 三、分条方式 〔一代〕
- 想分多条就用空格分隔；想沉默就只输出 [SILENT]。

## 三、分条方式 〔二代〕
- 用 qq_send_message 的 messages 数组分条；潜水用 qq_mark_read。

## 四、说话风格
- 这条没有标记 → 两种模式都会注入。
```

- 支持的写法：`〔二代〕`、`[v2]`、`（reserved2）`、`〔2 代〕`（一代同理：`〔一代〕`/`[v1]`/`（reserved）`）。
- 标记只是给桥接看的，**注入前会被去掉**，模型看到的标题是干净的。
- 没有标记的小节＝通用人设，两种模式都注入。
- 控制台打开某个人格时会显示「按模式注入：二代 N / 一代 M 字符」，并标出哪些小节会被跳过。

---

## 三、注入上限

- 默认**每条消息最多注入 6000 字符**（`config.json` 的 `role.maxInjectChars`，可设 1000~20000，控制台也能直接改）。
- 截断发生在**按模式筛完小节之后**，所以另一代的专属内容不会占掉本次预算。
- 这是成本护栏：人格卡会随每条消息一起发送，6000 字符约合 4~6k token。
- 控制台的人格列表会标出「超出上限」与各模式的实际注入字符数。

> 建议把人格卡控制在 3000~5000 字符：够写清人设，也不至于让每条消息都背上很长的前缀。

---

## 四、推荐结构（模板）

```markdown
# 角色卡：<角色名>

## 一、你是谁
- 身份、自我认知、别人怎么称呼你、你的雷点。

## 二、说话风格
- 句子长短、口头禅、标点习惯、用不用 emoji/括号。
- 明确写「不要什么」通常比写「要什么」更有效（例如：不要总结、不要升华、不要客服腔）。

## 三、性格与反应
- 被夸/被怼/被无视时分别怎么反应；有没有嘴硬、摆烂、傲娇之类的固定模式。

## 四、梗与背景（可选）
- 你的来历、和群友的关系、常用梗、角色梗的边界。

## 五、回复示例（示范语气与长度）
- 几条「群友说 → 你回」的例子。
- 例子只示范**语气和长度**，不要在这里规定分条机制（那是通用系统预设的事）。
```

## 五、其它提示

- 想改性格直接改文件内容；控制台保存后会重建人格 preset，**重启 DSH 后**新会话生效（人格模板不再每条消息注入）。
- 只写人格、不写工具；安全、硬约束与工具协议统一由通用系统预设负责。
- 角色名建议用简短中文（如 `傲娇助手`、`猫娘`、`吐槽役`）；不能与已有重名，也不能用 `README` 或 Windows 保留名（`CON`/`NUL`/`COM1`…）。
- 想临时关闭人格扮演，在控制台点「清除」；此时 AI 只按通用系统预设行动。
